# ratatui 0.30 upgrade (v0.18.0) — design

## Purpose

Move envision from ratatui 0.29 / crossterm 0.28 to ratatui 0.30.2 / crossterm 0.29 and leave 0.29 behind entirely. The driver is security: on `main` (`76dedb2`), `cargo audit` reports two advisories that only a ratatui upgrade can remove, because both crates are pulled in by ratatui 0.29 itself.

| Crate | Advisory | Kind | Path |
|---|---|---|---|
| `lru` 0.12.5 | RUSTSEC-2026-0002 (`IterMut` violates Stacked Borrows) | unsound | ratatui 0.29 |
| `lru` 0.12.5 | RUSTSEC-2026-0253 (use-after-free in `LruCache::pop()` on panic) | unsound | ratatui 0.29 |
| `paste` 1.0.15 | RUSTSEC-2024-0436 | unmaintained | ratatui 0.29 |

A throwaway probe resolved ratatui 0.30.2 + crossterm 0.29: the tree audits clean (`lru` 0.18.5, no `paste`). The upgrade also unblocks hyperlinks (#125) and supersedes #126 (dual 0.29/0.30 support via feature flags), which is closed rather than implemented — dual support would mean keeping the unsound, unmaintained 0.29 tree alive.

The project goal stated with this work: **the library should be as free of security issues as possible.** That goal shapes three choices below that go beyond a minimal bump: the exact version floor, the default-feature trim, and the follow-up audit gate.

This design was reviewed by five personas (downstream app developer, custom-backend author, Rust API/semver reviewer, security/supply-chain reviewer, CI/QA + MSRV packager) before being written; their must-fix items are folded in and attributed where they changed the design.

### MSRV PR (PR 2) — scope fixed here so PR 3 can assume it

- `rust-version = "1.88"`. ratatui 0.30.2 declares `rust-version = 1.88.0`.
- Raising `rust-version` alone (no ratatui change) produces **81 clippy errors** under `-D warnings` — 78 `collapsible_if` (let-chains stabilised in 1.88, so clippy's MSRV-gated lint activates) and 3 `manual_is_multiple_of`. Verified on `main` in a throwaway worktree. They are fixed in the MSRV PR, not in PR 3.
- CI matrix `rust: [stable, "1.85"]` is restructured so the MSRV leg is labelled `msrv` rather than a version number (e.g. `include: [{rust: msrv, toolchain: "1.88"}]`). The required-check names then never change on future MSRV bumps.
- Branch protection currently requires `Test (ubuntu-latest, 1.85)`, `Test (macos-latest, 1.85)`, `Test (windows-latest, 1.85)` (plus Clippy, Format, and the three stable legs). Sequence: PR fully green → one `required_status_checks` PATCH swapping the three 1.85 names for the three `msrv` names → merge immediately. Clippy, Format and the stable legs stay required throughout, so there is never a window with no required checks and no admin override is needed. This is a repository-settings change and is confirmed with the maintainer before it is made.
- Windows `RUSTDOCFLAGS` `/STACK` comment in `ci.yml` attributes the problem to "Rust 1.85": reworded, flag kept (merged doctests still apply on 1.88).
- Stale MSRV mentions: `README.md:388` (1.85), `CONTRIBUTING.md:10` (1.81). Historical CHANGELOG entries are left untouched.
- MSRV-aware resolution on 1.88 was verified: no resolved crate needs more than 1.88 (`time` 0.3.55 is exactly 1.88; `uuid` is held at 1.26.1).

## PR 3 design

### 1. Dependencies

```toml
ratatui = { version = "0.30.2", default-features = false, features = ["crossterm_0_29", "underline-color", "layout-cache"] }
crossterm = { version = "0.29", features = ["event-stream"] }
```

`serialization` keeps enabling `ratatui/serde` as today.

**Why `0.30.2` and not `0.30`** (security reviewer): `"0.30"` admits 0.30.0, whose ratatui-core 0.1.0 requires `lru ^0.16` — a consumer pinned there still resolves an `lru` flagged by RUSTSEC-2026-0253. 0.30.0 also lacks `CellDiffOption` (added `since = "0.30.1"`, `ratatui-core-0.1.2/src/buffer/cell.rs:12,67`), which § 4 depends on, and declares `rust-version` 1.86. The floor is what was tested.

**Why `crossterm_0_29` explicitly** (API reviewer): ratatui-crossterm selects the highest enabled `crossterm_0_xx` feature. envision also depends on crossterm directly (`src/app/runtime/terminal.rs` raw-mode and `execute!` calls). Naming the feature pins both to the same crossterm so they cannot silently diverge.

**Why trim default features** (security reviewer; maintainer decision): ratatui's defaults are `all-widgets` (= `widget-calendar`), `crossterm`, `layout-cache`, `macros`, `underline-color`. envision uses neither ratatui's calendar widget (it has its own `Calendar` component) nor `ratatui-macros`. Dropping them removes six crates from every consumer's tree, `time` among them. `underline-color` stays because `EnhancedCell` captures `underline_color` (`src/backend/cell/mod.rs:37`). The plan verifies that nothing behind a dropped feature is referenced (grep + `--no-default-features` build).

Consequence, documented in MIGRATION: `envision::ratatui` (§ 3) does not expose ratatui's calendar widget or macros. A consumer who wants them adds `ratatui` directly with those features; Cargo feature unification turns them on for the whole graph, so nothing breaks.

### 2. Backend error model

ratatui 0.30's `Backend` trait gained `type Error: core::error::Error`, and every method returns `Result<_, Self::Error>` (`ratatui-core-0.1.2/src/backend.rs:162-331`). This is the only source of compile breakage on the probe — six sites.

**Chosen model (all five personas): honest error types.**

- **`CaptureBackend::Error = core::convert::Infallible`.** CaptureBackend cannot fail; upstream's `TestBackend` makes the same choice (`ratatui-core-0.1.2/src/backend/test.rs:250`).
- **`DualBackend<P>::Error = P::Error`.** The capture half cannot fail, so every error is the primary's. No "which half failed" error type is needed.
  - Calls forwarded to the capture half are written `let Ok(()) = self.capture.draw(..);` (irrefutable since Rust 1.82). Using `?` there does not compile — generic `P::Error` has no `From<Infallible>` — and adding that bound would be needless. No `unwrap`/`expect` (security reviewer).
  - `DualBackend::with_auto_capture` and `DualBackendBuilder::build` only call `primary.size()`, so they return `Result<Self, P::Error>` / `Result<DualBackend<P>, P::Error>` instead of `envision::error::Result`. This keeps `DualBackend` usable with any backend without an envision-specific bound (custom-backend author).
- **`impl From<Infallible> for EnvisionError`**, body `match e {}` — no panic path.
- **Runtime bound: `EnvisionError: From<B::Error>`**, spelled this way because it is what `?` uses (the `B::Error: Into<EnvisionError>` spelling forces `.map_err(Into::into)` at each site). It goes **only on the impl blocks / methods that convert** (`Runtime::with_backend_state_and_config` at `src/app/runtime/mod.rs:211`, `RuntimeCore::render` at `src/app/runtime_core/mod.rs:45`, and whatever transitively calls them), never on struct definitions (`Runtime` at `src/app/runtime/mod.rs:105`, `RuntimeBuilder` at `builder.rs:168`, `ConfiguredRuntimeBuilder` at `builder_configured.rs:27`, `DualBackend` at `dual/mod.rs:43`). The existing `B: Backend` struct bounds are unchanged.
- Crossterm's error is `io::Error` (`ratatui-crossterm-0.1.2/src/lib.rs:230`), so terminal I/O failures keep surfacing as `EnvisionError::Io` via the existing `From<io::Error>`. Code matching `EnvisionError::Io` keeps working.

**Rejected:**
- *Keep `io::Error` on CaptureBackend; box everything else into `Other`* — silently reclassifies crossterm I/O errors from `Io` to `Other` with no compile error, and CaptureBackend would advertise failures it cannot produce.
- *New `EnvisionError::Backend` variant* — a second breaking change for no gain over the chosen model.
- *Bound `B::Error: Error + Send + Sync + 'static`, boxed, with a runtime downcast to `io::Error`* (custom-backend author's alternative) — works for foreign error types with no user code, but decides the variant at runtime and excludes non-`Send` errors. The chosen bound is stricter, and **loosening a bound later is not a breaking change**, so starting strict keeps this option open. The orphan-rule cost of the chosen bound — a backend whose error type is foreign to the consumer needs a newtype wrapper — is documented in MIGRATION. All four official ratatui backends (crossterm, termion, termwiz, termina) use `io::Error`, so none of them hits it.

**`#[non_exhaustive]` on `EnvisionError`** (`src/error.rs:46`; API reviewer; maintainer decision). v0.18.0 is already breaking, so this is its cheapest moment; afterwards, adding a variant (e.g. a dedicated backend error) is non-breaking. Consumers that `match` exhaustively need a `_ =>` arm.

### 3. Re-exports (maintainer decision)

- **`pub use ratatui;`** at the crate root. envision's public API already exposes ratatui types throughout (`src/layout/mod.rs:47-49`, `src/style/mod.rs:21`, `src/lib.rs:489-492`, `TerminalRuntime` at `src/app/runtime/mod.rs:158`, `EnhancedCell::from_ratatui_cell`), so the upgrade is breaking regardless. Re-exporting lets consumers use exactly envision's ratatui (and, through it, `ratatui::crossterm`) and avoid the two-versions failure mode — "expected `ratatui::Frame`, found `ratatui::Frame`" — that the README's current `cargo add envision` + bare `use ratatui::…` invites (`README.md:56-63`). The README snippet is updated to use the re-export.
- **`Backend` trait re-exported** from `envision::backend`. It appears in envision's public bounds and must be implemented by custom-backend authors, but is not exported today.
- **`HorizontalAlignment` and `VerticalAlignment`** join `Alignment` in `envision::layout`. In 0.30, `Alignment` is a type alias for `HorizontalAlignment` (`ratatui-core-0.1.2/src/layout/alignment.rs:8`).

### 4. Captured cells — `SerializableDiffOption` mirror

ratatui 0.30.1 deprecated `Cell::skip: bool` in favour of `diff_option: CellDiffOption { None, Skip, AlwaysUpdate, ForcedWidth(NonZeroU16) }`. envision reads it at `src/backend/cell/mod.rs:84` into `EnhancedCell { pub skip: bool }` (`:43`).

**Chosen (4 of 5 personas; maintainer decision): replace `skip: bool` with a serializable mirror.**

```rust
#[non_exhaustive]
pub enum SerializableDiffOption { None, Skip, AlwaysUpdate, ForcedWidth(NonZeroU16) }
```

- Named `SerializableDiffOption`, following the existing `SerializableColor` / `SerializableModifier` convention for serializable mirrors of ratatui types. It lives in `src/backend/cell/` beside `EnhancedCell` and is exported wherever `EnhancedCell` is. The field on `EnhancedCell` is `pub diff_option: SerializableDiffOption`.
- **Mapping copies upstream's effective rule, not the naive one** (CI/QA reviewer). Upstream diffing treats a cell as skipped when `diff_option == Skip || (skip && diff_option == None)` (`ratatui-core-0.1.2/src/buffer/diff.rs:201-205`, `is_skip`), so the deprecated field is still honoured. The mirror is therefore `Skip` when upstream's `diff_option` is `Skip`, *or* when it is `None` and the deprecated `skip` is `true`; otherwise it is the upstream value. Reading the deprecated field happens in exactly one function, under a scoped `#[allow(deprecated)]` with a comment pointing at `is_skip` — the same thing upstream does. Third-party widgets still calling `set_skip(true)` are then captured correctly.
- **Serde:** `#[serde(default, skip_serializing_if = "SerializableDiffOption::is_none")]`. Ordinary cells serialize with no diff-option field at all, previously-saved JSON (which has `"skip": …` and no diff-option field) still deserializes, and future variants (hyperlinks, #125) do not churn golden files again. `NonZeroU16` makes serde reject a zero width; no extra validation code.
- **One-time JSON format change**, accepted for v0.18.0: every cell drops `"skip":false`. This touches `SnapshotTest` golden files (compared as text, `src/harness/snapshot/mod.rs:418-421`) and the pinned JSON in `src/backend/capture/tests.rs:606`. MIGRATION gives the regeneration step (`with_update(true)`).

### 5. Snapshot changes — 14 tests, proven upstream

Probe result: 7450/7464 nextest pass, 2578/2578 doctests pass. The 14 failures are insta snapshots — 11 in `component::chart` (incl. `x_labels_tests`) and 3 in `component::canvas` — where braille dots move by about one sub-cell.

Two upstream changes explain them (CI/QA reviewer):
1. **Rounding:** grid mapping changed from truncation (`ratatui-0.29.0/src/widgets/canvas.rs:402-403`, `as usize`) to rounding (`ratatui-widgets-0.3.2/src/canvas.rs:460-461`, `.round() as usize`).
2. **Line clipping:** lines with an out-of-bounds endpoint were dropped in 0.29; 0.30 clips them (Cohen–Sutherland in `canvas/line.rs`) and draws the visible segment. Snapshots with Y ranges or thresholds may change for this reason rather than rounding.

Acceptance is by evidence, not eyeballing:
- Each of the 14 diffs is labelled "rounding" or "clipping" in the impl PR description.
- A script (kept in the scratchpad, output pasted into the PR) shows every changed character is in U+2800–U+28FF or a space — axes, labels, borders and legends are untouched.
- An envision test pins upstream rounding directly (e.g. a 2×2 braille `Context` over `[1.0, 2.0] × [0.0, 2.0]` maps `(1.5, 1.0)` to grid `(2, 4)`), so a future upstream change surfaces as a named test failure rather than snapshot noise.
- Updated `.snap` files land in a commit containing nothing else.

### 6. Other upstream fallout

- `ListState` is now `Copy`: four `clone_on_copy` sites are fixed.
- The D3 column-clip warning (`src/component/table/render.rs:209-250`) mirrors ratatui's Table width formula. ratatui 0.30's `get_column_widths` (`ratatui-widgets-0.3.2/src/table.rs:1041-1065`) has the same structure — selection `Length` + `Fill(0)`, `Flex::Start`, `column_spacing` 1 — so only the "ratatui 0.29" citations are updated, with new line references. Its existing 12 tests stay green unchanged.
- Changes that do not affect envision's code but reach consumers through re-exports are documented, not worked around: `Frame::render_widget_ref` removed (now behind `unstable-widget-ref`); `Terminal::new`/`Terminal::draw` return `B::Error`; `Style` serde output omits `None` colours and empty modifiers (`ratatui-core-0.1.2/src/style.rs:236-266`), which changes serialized `KeyHintsState` / `TitleCardState` JSON (old JSON still reads); `Flex::SpaceAround` changed meaning and `Flex::SpaceEvenly` was added.

### 7. Residual consumer risk — `lru` floor

Even with the `0.30.2` floor, ratatui-core 0.1.2 requires `lru = "0.18"`, which admits 0.18.0 and 0.18.1, which are still affected by RUSTSEC-2026-0253 (fixed in 0.18.2). The security reviewer reproduced this with `-Zminimal-versions`. envision cannot fix it without adding an unused direct `lru` dependency purely to force a floor, which is rejected as a hack.

Resolution (maintainer decision):
- PR 8 asks ratatui-core to require `lru >= 0.18.2`. When a fixed ratatui ships, envision raises its ratatui floor to it.
- CHANGELOG carries a security note telling consumers to run `cargo update -p lru` (any normal resolution already picks 0.18.5).
- envision's own lockfile must resolve `lru >= 0.18.2` (acceptance criterion below).

## Testing strategy — tests first

Written and seen failing (or failing to compile) before the dependency bump, then made to pass by it:

1. **Type-level:** `<CaptureBackend as Backend>::Error` is `Infallible` (static assertion).
2. **I/O classification preserved:** a crossterm-style `io::Error` raised through `Runtime` surfaces as `EnvisionError::Io`.
3. **Injected draw error reaches the runtime:** a test backend whose `draw` fails makes the runtime's render/tick return the expected variant.
4. **Foreign error type:** a compile test (trybuild is already a dev-dependency) with a custom backend whose `Error` is a newtype around an error from another crate, used through `Runtime::builder` and wrapped in `DualBackend`, compiles. A second case without the `From` impl fails to compile with the documented error.
5. **`DualBackend` constructors** return the primary's error unchanged.
6. **`SerializableDiffOption` mirror:**
   - each upstream variant maps across;
   - the deprecated `skip == true` with `diff_option == None` maps to `Skip`;
   - JSON round-trips every variant;
   - ordinary cells serialize with no diff-option field;
   - legacy JSON containing `"skip": false` deserializes;
   - `ForcedWidth(0)` is rejected.
7. **Rounding pin** (§ 5).
8. **`EnvisionError` is `#[non_exhaustive]`:** a trybuild case where an exhaustive external `match` without `_` fails to compile.

## Commit order (impl PR)

1. Failing tests (above).
2. Dependency bump + backend/error changes + re-exports + `SerializableDiffOption` mirror + `clone_on_copy` fixes + D3 citation update — tests from step 1 pass.
3. Snapshot-only commit (the 14 `.snap` files).
4. CHANGELOG, MIGRATION, README.

All commits signed. `cargo fmt` before each.

## CHANGELOG / MIGRATION content

Under `[Unreleased]` and MIGRATION § *v0.17.x to v0.18.0*, ordered by how early a consumer hits each:

1. **Minimum versions:** MSRV 1.88; `ratatui = "0.30.2"`; `crossterm = "0.29"`. Show the two-versions error ("expected `ratatui::Frame`, found `ratatui::Frame`") and its fix: bump, or use `envision::ratatui`. Link ratatui's 0.30 breaking-changes notes.
2. **Security note:** advisories removed; run `cargo update -p lru` (§ 7).
3. **Backend errors:**
   - `CaptureBackend` methods return `Result<_, Infallible>`, so `?` into an `io::Result` function no longer compiles — use `let Ok(x) = backend.size();`.
   - Custom `Backend` impls need `type Error`.
   - The runtime requires `EnvisionError: From<YourBackend::Error>`; a foreign error type needs a newtype backend.
   - `DualBackend` constructors return the primary's error type.
4. **`EnvisionError` is `#[non_exhaustive]`:** add a `_ =>` arm.
5. **`EnhancedCell.skip` replaced by `diff_option`:** JSON golden files change once; regenerate with `with_update(true)`. Old files still load.
6. **Rendering:** chart, canvas and braille output shifts by up to one sub-cell, and out-of-bounds line segments are now drawn clipped. Consumers' own snapshots containing these will change; run `cargo insta review`.
7. **Re-exports:** `envision::ratatui`, `envision::backend::Backend`, `HorizontalAlignment` / `VerticalAlignment`. Default-feature trim: ratatui's calendar widget and macros are no longer enabled by envision.
8. **Upstream changes visible through envision:**
   - `ListState: Copy`, so `.clone()` trips `clippy::clone_on_copy`;
   - `render_widget_ref` removed;
   - `Alignment` is an alias for `HorizontalAlignment`;
   - `Style` serde output changed;
   - `Flex::SpaceAround` changed meaning.

## Risk register

| Risk | Mitigation |
|---|---|
| Hidden breakage in tests/examples only visible after the lib compiles | Probe already compiled every target and ran the full suite; remaining work is the 14 snapshots. |
| Snapshot churn masks an envision regression | Braille-only diff script + per-diff cause label + rounding pin test (§ 5). |
| Feature trim removes something envision uses | Plan verifies by grep and a `--no-default-features` build before the trim commit. |
| Consumer resolves vulnerable `lru` 0.18.0/0.18.1 | CHANGELOG note; upstream PR 8; floor raised when upstream ships. |
| Branch-protection names drift on future bumps | `msrv` matrix label (PR 2). |
| Error context lost: a `Terminal::new` failure and a draw failure render the same `Io` message | Accepted for this release. `Io` preserves the source error. Recorded in Known Deferred Findings as a candidate for a context-carrying variant, now non-breaking thanks to `#[non_exhaustive]`. |
